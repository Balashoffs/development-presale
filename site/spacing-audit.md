# Аудит отступов между блоками — страницы кроме главной

> **Назначение.** Этот документ — снимок текущих вертикальных отступов в `src/pages/*.astro` на момент работы по задаче "межблочная нормализация 60/40". Главная страница (`index.astro` через компоненты `HeroBlock` / `AboutBlock` / `ServiceBlock` / `CasesBlock`) уже приведена к спеке. Для остальных страниц **изменения не вносились** — только фиксируется состояние и расхождения со спекой.
>
> Использовать как чек-лист при следующем подходе к нормализации.

## Спека (контракт)

| Контекст | mobile | md (≥768) | lg (≥1024) | xl (≥1280) |
|---|---|---|---|---|
| Между нижней кнопкой блока и заголовком следующего блока | 32 | 40 | 48 | **60** |
| Между нижней группой текста и первой кнопкой блока | 24 | 32 | 36 | **40** |

Спека применяется к парам **«блок с CTA-кнопкой → следующий блок»**. Для пар без кнопки в предыдущем блоке решение откладывается на отдельную итерацию.

## Подкатегории каталога

Файлы вида `src/pages/catalog/**/*.astro` и `src/pages/equipment/*.astro` (≈ 10 страниц) повторяют один и тот же паттерн:

```
<Breadcrumb /> + page-title `py-[16px] md:py-[24px] lg:py-[32px] xl:py-[40px]` + content `pb-[40px]`
```

Никаких CTA-кнопок внутри секций. Расхождений со спекой нет.

**Низкий приоритет / не входит в спеку:**

## Метод сбора (как воспроизвести)

1. `grep -RnE "<section[^>]*\bpy-|<section[^>]*\bpt-|<section[^>]*\bpb-" src/pages/`
2. Для каждой секции выписать каноническую шкалу `mobile / md / lg / xl`. Если значение не указано на каком-то брейкпоинте — наследуется от предыдущего меньшего.
3. Найти CTA — `<button>` или `<a>` с классом `bg-konex-blue` и атрибутом `href` или `data-feedback-topic` внутри секции.
4. Сложить `pb_n` и `pt_(n+1)` соседних секций на каждом брейкпоинте, сравнить со спекой.
